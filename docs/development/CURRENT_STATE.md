# Current state

## Product and runtime

workflow-integrated is the active integration product branch, anchored to the workflow-C production baseline at d600ed4. The supported environment is Windows, Miniforge environment workflow-c, Python 3.11, Pillow, Tkinter, Fiji/ImageJ, ROI 1-click Tools, and AutoHotkey v2.

Start with start_controller.cmd. It validates exact Python 3.11 plus Pillow and Tkinter for every candidate and never tries another interpreter after the controller has run. start_custom_matrix.cmd uses the same contract.

## Portable pre-release

`tools/build_portable_release.py` creates a requested pre-release ZIP (the default remains `dist/workflow-integrated-prerelease.zip`) from an explicit tracked runtime allowlist. The archive includes Windows launch/setup files, required Python/AHK/Fiji/legacy renderer assets, JSON contracts, and anonymous sample CSVs. It excludes Git metadata, repository docs/tests/fixtures/V10 data, caches, images, personal paths, AI/development material, and user state. The current artifact passes deterministic archive checks, anonymity/content scanning, extracted Python compilation, direct-script import probes for every packaged Python entry point from outside the application root, and packaged sample-CSV validation. Controller-launched Python helpers explicitly use the portable application root as their working directory.

## Active endpoints

The controller provides project setup and CSV discovery; metadata reconciliation/preflight; all-folder, subfolder, single, and rerun four-point processing; and one unified **Build matrices and labelled crops** applet. Four-point processing defaults to crop export and also offers an explicit, non-persisted **Register grid only (no crops)** option. Register-only uses the same proven placement/QC/handoff path, writes the durable grid asset, and skips crop bounds/archive/write/state operations. It cannot be combined with rerun or replacement.

**Open V10 project applets** launches the stateful rich-metadata workflow. Setup can prepare one experiment folder or every dated experiment subfolder under a parent. Folder dates accept `dd.mm.yy`, `dd-mm-yy`, `dd_mm_yy`, `yyyy.mm.dd`, `yyyy-mm-dd`, or `yyyy_mm_dd`; matching uses V10 `Date*`, then Exp/session and `Original` evidence, with a manual sessionUID choice only when ambiguity remains. Loose originals move unchanged into numbered Raw, Working receives UID-safe copies, and a project-relative human audit map records every copy/name. Existing state and old folder names are resumed rather than replaced; old folders can be upgraded only after confirmation.

The numbered V10 project tree is `1. a. Raw`, `1. b. Working`, `2. Cropped`, `3. Processed`, `4. Annotated`, `5. Individual Crops/{Unprocessed,Processed}`, `6. Matrices`, and `z. Metadata/State/GridCoordinates`. Working may be marked complete manually or moved automatically to `2. Cropped/1. b. Working` after all project crops are accepted/skipped. Project state stores a stable project ID and relative state location, rebases in-project paths after an external or programmatic project-folder rename, and preserves external workbook paths.

Setup can render Working names as recorded in V10 or replace their date with `yyyy.mm.dd` using canonical `Date*`. Renaming the experiment-folder date is a separate option and remains compatible with later external folder renames. The default review toggle keeps the explicit Preview/confirmation flow; when review is disabled, Apply performs the same safe preview internally and proceeds without an extra user step. Settings persist globally and per project. Annotation defaults to Processed, then Cropped, then Working; explicit Processed/Cropped/Working radios are available. Culture export has explicit Working/Cropped/Processed source selection. Accepted grid JSON is found recursively under canonical and legacy project grid folders; unique matches attach automatically and ambiguity is reported.

The same window now includes **Quick Figures** in both embedded and detachable form. It accepts any selected image plus either a minimal `Pos,Strain` CSV or compatible V10/current names such as `labels_strain`, without project/V10 identity verification. It supports fixed orientation, dragged-edge alignment, whole-figure crop, durable two-endpoint 1×N `r1cN` registration with optional QC, quick date/figure-description entry, grid-derived annotation, and immutable long rectangular per-well exports. The detached form cannot recursively create more detached windows, and plain-letter shortcuts remain suppressed while lists or editable controls have focus.

Annotation provides master/per-field header controls and a separate in-image section. Date, figure description, plate, condition, session, and media have independent visibility, ordering, font, size, colour, boldness, rotation, and offsets. Strain/vertical styles and exact per-strain colours are separately configurable. Named presets, custom hex colours, system-font browsing, and last-session restoration are local user settings, not project data. Enabling the figure-description field initially disables plate/condition, which may then be re-enabled.

The **Batch** tab selects project images once. Setup remains project-wide; orientation and plate crop run as manual advance queues that omit already accepted/skipped images while retaining stale/missing work; grid assets are uniquely matched from a folder; culture, visibility, and annotation preflight every selected image before the first accepted write. Culture crop dimensions can be calculated from manually entered Fiji ROI left/top/right/bottom coordinates and saved as named presets. Accepted or skipped culture work records its exact tier/source/states/columns/dimensions signature, so reopen resumes at the next unfinished image while changed controls correctly create new pending work. Outside an explicit queue, accepted/skipped orientation, crop, grid, culture, visibility, and annotation actions advance to the next project image by default; this is a saved Setup option. Repeated applet actions use tab-scoped lower-left keys: `X` start/retry, `V` preview, `Z` accept/export, and `C` skip/next, with nearby stage-specific keys. A collapsed **Hotkeys** panel in the window lists every binding; bindings are disabled while typing. Existing `Alt+O`, `Alt+C`, `Alt+B` and Quick Figures `Ctrl` shortcuts remain available.

Orientation supports either a dragged edge line or two clicked points, with automatic preview by default and saved last-used mode. On Windows the Tk 8.6 UI uses Windows-managed whole-window scaling rather than forcing Per-Monitor-v2. Pointer positions are normalized within the live native canvas client rectangle before being mapped through the current Tk canvas and rendered-image transform, so logical/device scaling cancels instead of being guessed. The calibration result reports its normalized route and native client dimensions. The same mapping protects Quick Figures interaction. The reusable crop rule defaults to no margin and rounding down to the nearest 50 pixels, with saved controls for disabled/down/nearest/up rounding, increment, and per-side pixel or percentage margin. Calibration absorbs at most one displayed pixel of source-coordinate quantization when a measured side falls immediately beside a rounding increment, preventing a true 1750-pixel span from dropping to 1700 while retaining ordinary round-down behavior. Named measured or exact crop sizes appear in a selectable project preset list, and the active selection survives reopen. A known exact final side may instead be accepted numerically without calibration clicks. Crop placement automatically previews by default. Accepted transformed orientation, whole-plate crop, and visibility files are lossless PNG derivatives at their calculated pixel dimensions; originals and skipped exact-copy outputs retain their source files/formats.

The basic CSV matrix endpoint remains available. One numbered applet run can publish any combination of per-experiment, selected all-strain, duplicate-WT-removed all-strain, and individually labelled outputs, with dataset presets, preferred-WT selection, optional separator normalization, recipes, and consolidated processing logs.

Retired user routes are the controller Pillow dropdown, separate preferred-WT applet, full-column detector, global-visibility launcher, presentation-normalized output, generic dedup CLI, partial-output flag, and direct unrecorded custom entrypoints. Their proven Pillow helpers remain internal to the unified endpoint.

## Alignment and export

The active route uses R1C1, R1C-last, R5C1, and R5C-last to interpolate the 8 by N grid mathematically. The installed ROI 1-click Rotated Rectangle Click Tool supplies placement. A disposable whole-image duplicate receives two CLAHE passes; source pixels remain unchanged.

QC is optional. Accept exports and Retry repeats placement. Without QC, export follows four clicks. Both paths bounds-check every Top and Low rectangle before replacement archiving and before the first crop write. Crop dimensions default to 130 by 546 and remain configurable.

Rerun reads authoritative images.csv and always forces a replacement manifest. Ordinary single remains pending-only. Selected files must be inside image_root. After accepted crop export—or after accepted register-only QC—batch and single routes persist a versioned GridCoordinateAsset beside project metadata. It records the explicit source-image pixel coordinate system, four measured references, row/column geometry, and named spots such as r1c1. Default export ordering remains bounds-check all crops, archive replacements, write crops, record crop completion, then publish the grid handoff.

## Lifecycle and AHK

Batch handoff is TSV keyed by folder plus filename. The controller checks ROI readiness, tracks only owned processes, and does not call wrapper exit a crop success. Success requires the Fiji macro completion sentinel. Cancel exits cleanly; restart writes a resume marker and relaunches; early or nonzero exit fails closed.

Generated Fiji macros do not use ImageJ `print`, so runs do not create a separate Log window. Completed Batch All, Batch Folder, Single, and Single Rerun sessions append to the dataset-level `matrix_output/Processing Logs/Four-Point Alignment Runs.txt` under sequential `Run NNN` dividers; interrupted sessions are not recorded as completed.

Windows PID liveness uses OpenProcess and WaitForSingleObject. Never use os.kill(pid, 0) on Windows because it terminates for non-console signals.

The AHK v2 helper restricts Java-frame and shell-hook handling to fiji-windows-x64.exe. Preserve launcher AlwaysOnTop removal plus MoveBottom, native toolbar placement, source hiding, owned-window cancel cleanup, 1.8-second duplicate prompt containment, and AHK restart signaling. RMI, socket, and direct ij.ImageJ attachment failures remain documented in docs/research/fiji-four-point-runtime.md.

## Data and outputs

CSV validation rejects unheaded extra fields, Windows case-only identities, unsafe output components, and Strain values that sanitize to the same folder. Reconciliation, finalization, freshness, and inventory use case-insensitive Windows identity while retaining physical spelling.

The read-only V10 adapter preserves the workbook and canonical terminology, and validates required schema, field types/mappings, duplicate identities, missing values, starred machine columns, `sessionUID`/`Image UID`, profile `Pos`, and strain-profile `Order`. It embeds explicit `PlateLayout` row-band provenance. Setup immediately creates immutable numbered CSV snapshots plus active copies under `z. Metadata`: `v10_master_registry.csv`, lossless `v10_plate_layout.csv`, compatibility `images.csv` and `condition_order.csv`, and `grid.csv` only when the rich row-band layout can be flattened without losing labels. Users can keep the current snapshot, compare it with the linked workbook, or explicitly refresh from V10; removed Image UIDs are retired rather than silently discarded.

Saved-grid culture export validates every requested Top/Low rectangle before writing, publishes immutable numbered runs under distinct `5. Individual Crops/Unprocessed` and `5. Individual Crops/Processed` parents, and records source/grid/layout provenance. Mixed-tier composition accepts only current recorded crops, permits Top and Low choices in one matrix, previews without writes, validates a complete requested layout, and publishes immutable numbered runs under `6. Matrices/Mixed Tier`.

The unified Pillow endpoint filters to selected groups/strains, conditions, and Top/Low states, then requires exact current crops only for that selected metadata contract. It stages disposable copies, normalizes only staging, runs all checked mature renderers before publishing, and never overwrites past numbered runs. Matrix outputs are categorized and copied to `!All Matrix Exports`; labelled crops are grouped by Experiment/Strain and excluded from the aggregate.

Custom composition is Raw only. Presentation recipes and direct presentation shims fail explicitly. Deduplicated all-strains output requires a selected WT Experiment/Set; names record actual retained WT provenance in experiment order, with numeric Sets before lettered Sets.
